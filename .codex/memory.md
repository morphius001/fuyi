# Codex Project Memory

本文件记录本项目内主 agent 的长期工作偏好。每次开始任务、恢复任务或执行队列前，都应先读取本文件。

## 用户偏好

- 用户希望主 agent 对整个中国本地化计划负责，而不是只完成单点任务。
- 用户希望任务交给并行 AG 时，主 agent 负责分配、汇总、验证和风险判断。
- 用户希望主 agent 不需要反复等待“继续”。当一个任务完成且验证通过后，应自动开始下一轮。
- 用户希望看到当前做到哪里、剩下什么、哪些能通、哪些有风险。
- 用户不希望 Codex 自动 commit、push、创建 PR，除非明确要求。
- 用户明确担心“本地乱改导致后期上线不知道怎么改”。主 agent 做任何本地开发配置、端口、URL、账号、mock provider、feature flag 或环境变量相关修改前，必须说明这是本地配置还是可上线配置，并把上线替换方式写清楚。

## 本地与上线配置边界

- 不要在业务代码里硬编码只适用于本机的地址、账号、端口、路径或开关。
- 本地可用的默认值必须通过环境变量覆盖，例如 Admin 后端地址应允许用 `VITE_MEDUSA_BACKEND_URL` 指向生产/测试后端。
- 如果为了本地调试临时改了配置，完成后必须整理为“环境变量优先 + 本地默认兜底”，或者记录为待回滚项。
- 本地开发账号只能用于本地数据库，并在总结里标记为 local dev credential；不要写真实生产账号或密钥。
- 上线前必须检查 `.env*`、Vite/Next config、provider config、CORS、cookie/session 域名、feature flag、mock provider 开关，确保没有 `127.0.0.1`、`localhost` 或 mock 默认值被当成生产配置。
- 每次涉及配置的任务，最终输出必须包含：本地配置值、上线应配置的环境变量、是否影响生产、如何回滚。

## 自动队列规则

- 当用户说“开始”、“继续”、“按照你的来”、“你来操作”、“任务完成了就继续下一轮”等指令时，进入自动队列模式。
- 自动队列模式下，每完成一个任务并通过验证后，立即读取 `.codex/queue.md`，执行下一个未完成且未标记 `local-wip` 或 `done` 的任务。
- 如果 `.codex/queue.md` 没有可执行任务，主 agent 应主动提出下一批建议任务，并在文档/队列中固化后继续，除非用户要求先停。
- 自动队列模式下，阶段性更新只需要说明当前任务、验证结果和下一步，不要反复询问是否继续。

## 暂停条件

遇到以下情况必须暂停并向用户说明：

- 任务会触碰支付、订单、退款、结算、佣金、权限等高风险业务逻辑。
- 任务需要真实密钥、真实支付、真实短信、真实 IM、真实物流、真实直播或真实快递打印。
- 任务需要删除文件、移除 worktree、运行 destructive git 命令。
- 构建、测试、类型检查或页面连通性验证失败。
- 需要用户视觉确认后才能判断是否满意。
- 用户明确说“停止”、“暂停”、“不要自己动手”或要求只分配给 AG。

## 当前产品方向

- 本项目是中国大陆本地生鲜/海鲜多商户平台，不是普通通用商城。
- 前台以市场、店铺/档口、今日鲜货、搜索找货/找店为核心。
- 商户端要支持手机快速上架、AI 草稿上架、店铺装修、物料采购、配送供应商、上游货源和快递打印占位。
- 后台要控制哪些模块开放、哪些模块不开放；最终必须由后端 feature flag、权限和审计共同控制。
- 提货卡是消费者已有权益的提货凭证，不是优惠券、储值卡、支付方式或购物车抵扣。
- 支付成功必须以后端异步通知为准。

## 本地后台入口

- 中国平台运营后台首页使用 `http://127.0.0.1:7000/dashboard/cn`。
- 直接打开 `http://127.0.0.1:7000/dashboard/login` 登录时，Mercur/Admin 默认登录成功地址可能仍回到内置 `/orders`；这是上游 Admin 的默认登录回跳，不代表中国首页是订单页。
- 需要验证中国后台首页时，优先打开 `/dashboard/cn`；如果未登录，会先跳到登录页，登录成功后再回到 `/dashboard/cn`。
