# Admin Dashboard Template V2 Plan

更新时间：2026-05-09 Asia/Shanghai

## 目标

规划平台运营后台首页 v2 模板预览。后台首页要像国内平台运营后台：信息密度适中、首屏可扫描、工具靠右、待办和风险清楚，不像订单页误当首页，也不把 mock 指标当真实交易事实。

当前不改页面，只定义后续实现验收。

## Template ID

```text
admin-dashboard-ops-v2
```

## 读取 View Model

后续实现应只读取稳定展示模型：

```text
header_tools
kpi_cards
operation_todos
risk_alerts
quick_actions
focus_modules
data_source_notice
responsibility_table
```

不能直接读取或改变：

- RBAC / permission
- audit log
- payment success
- order status
- refund status
- settlement / commission / payout
- fulfillment / waybill
- provider config
- real credentials

## 页面结构

建议 Admin 首页 v2：

```text
顶部区域：
  左侧：页面标题、版本/环境标签、简短说明
  右侧：搜索、待办、消息、平台管理员
首屏 KPI：
  交易额、订单数、待审核商户、待处理售后、上架商品、服务异常
主体两列：
  左：运营待办
  右：风险提醒
第二行：
  快捷入口
  数据来源说明
底部：
  业务入口与职责说明
```

## 顶部工具规则

顶部搜索、待办、消息、用户入口必须靠右，并与标题区同一视觉层级。

禁止：

- 把工具条放在标题正文中间。
- 让顶部大面积空白。
- 工具条把主标题挤开。
- 工具条和面包屑混在一起。

## 信息密度规则

后台首页不是营销页。卡片应该：

- 高度紧凑。
- 行距适中。
- 数字醒目但不夸张。
- 首屏能看到 KPI、待办和风险。
- 表格/列表区域不要动辄占满整屏空白。

需要避免：

- 每个指标卡占一整行。
- 说明文字过长。
- 底部大块空白。
- 一眼看不到运营重点。

## 指标和数据来源

如果数据仍是展示数据，必须明确：

- 当前是展示/只读/占位数据。
- 不读取真实订单、支付、库存、结算或权限。
- 后续接真实数据需要单独后端任务。

模板不能：

- 把 mock 指标当真实交易事实。
- 根据前端展示直接判断支付成功。
- 根据前端展示直接判断订单、退款、结算或履约状态。

## 待办和风险

运营待办建议：

- 商家入驻审核。
- 商品上架审核。
- 售后异常。
- 服务通知异常。
- 提货卡异常。

风险提醒建议：

- 配送超时。
- 商户近期差评上升。
- 库存异常。
- 直播互动下降。
- 提货卡异常提货。

待办和风险可以跳转到只读占位页或后续真实页面，但模板不能直接执行高风险动作。

## 快捷入口

快捷入口建议保留：

- 审核商品。
- 配置市场。
- 查看商家。
- 订单监管。
- 模块开关。
- 能力合同。

快捷入口如果指向真实高风险页面，必须依赖后端权限和审计，不由首页模板决定。

## 验收清单

后续实现 PR 必须验证：

- 桌面截图：首屏包含标题、右侧工具、KPI、待办、风险。
- 顶部工具在右侧，不在标题中间。
- KPI 不再一张卡占一整行。
- 首页不是订单页或单一列表页。
- 数据来源说明明确 mock/展示边界。
- 无 `chinaAdmin.*` i18n key 泄漏。
- Admin lint/build 通过。
- 不修改 RBAC、审计、支付、退款、结算、佣金、打款或履约 runtime。

## 回滚方式

实现时必须保留：

- 可切回 `admin-dashboard-ops-v1` 的模板 id。
- 旧首页壳或旧 dashboard route 入口。
- 不改变真实权限和操作。
- 不改变 API route 或数据库。

## 本轮结论

Admin 首页 v2 的目标是“运营一眼看懂今天要处理什么”。它可以换布局，但不能把前端模板变成真实业务事实来源。
