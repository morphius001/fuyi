# Admin Template Contract Plan

更新时间：2026-05-08 Asia/Shanghai

## 目标

为平台运营后台建立模板合同。后续 Admin 可以继续向国内平台运营后台靠拢：左侧菜单、顶部工具、数据看板、待办、风险提醒、表格和详情页都可以模板化，但模板层不能替代真实权限、审计、交易和履约事实。

本任务只做规划，不修改 `apps/admin/**`。

## Admin 定位

Admin 是平台运营后台，服务对象是平台运营人员，不是消费者和商户。

它应该回答：

- 今天平台发生了什么。
- 哪些商户、商品、订单、售后、配送、提货卡、风控事项需要处理。
- 哪些模块只是配置展示，哪些模块已经接入真实后端。
- 哪些动作高风险，必须有权限、审计和后端确认。

## 后台首页模板合同

首页模板建议由这些 slot 组成：

```text
header_tools
kpi_cards
operation_todos
risk_alerts
quick_actions
focus_modules
data_source_notice
responsibility_table
```

首页可以展示：

- 今日交易额、订单数、待审核商家、待处理售后、商品数、服务通知异常等运营指标。
- 商家入驻审核、商品上架审核、服务通知异常、风险预警等待办。
- 市场、商户、商品、订单、售后、提货卡和风控的快捷入口。
- 当前数据来源说明。

首页不能展示或不能执行：

- 直接确认付款成功。
- 直接退款。
- 直接结算或打款。
- 直接修改佣金。
- 绕过 RBAC 的高风险操作。
- 真实发货、真实面单打印或真实履约确认。

## 菜单模板合同

菜单模板应该支持国内平台运营的信息架构：

```text
首页
平台运营
  平台设置
  市场配置
  商户类型开关
商户商品
  商户管理
  商品管理
  商品审核
  规格模板
交易履约
  订单管理
  售后管理
  提货卡管理
财务风控
  支付与对账
  结算管理
  风控管理
内容服务
  营销中心
  客服与消息
  直播管理
系统配置
  权限管理
  系统设置
  应用中心
```

菜单可以隐藏、折叠、分组和重命名，但不能改变真实权限判定。真实可见性必须由后端权限、模块配置和审计规则决定。

## 市场运营模板合同

市场运营模板应覆盖：

- 市场列表。
- 市场详情。
- 档口关系。
- 商户跨市场归属。
- 营业时间。
- 公告。
- 配送规则。
- 统一配送能力和商户自行配送开关。

模板只展示和编辑已授权的配置视图。真实配送规则影响 checkout 或履约时，必须进入单独高风险任务。

市场 view model 建议：

```text
market_profile
market_memberships
stall_layout
business_hours
announcements
delivery_profiles
module_status
audit_summary
```

## 商户管理模板合同

商户管理模板应覆盖：

- 普通生鲜/海鲜商户。
- 水果蔬菜商户。
- 物料供应商。
- 配送供应商。
- 养殖户/种植户。
- 种苗供应商。
- 外地批发商。
- 跨市场归属和档口号。
- 资质、状态、风险和操作记录。

商户模板可以展示角色能力矩阵，但不能把 UI 开关当真实权限。真实商户类型生效、结算主体、经营范围和权限必须由后端合同处理。

## 商品审核和规格模板合同

商品模板应支持：

- 商品列表。
- 商品审核。
- 分类管理。
- 规格模板。
- 品牌管理。
- 禁售规则。
- 手机快速上架草稿审核。
- AI 上架草稿审核。

模板可以展示审核状态和字段完整度，但不能直接绕过商品创建 workflow、库存校验或权限控制。

## 提货卡运营模板合同

提货卡模板必须独立于优惠券和支付方式：

- 卡种。
- 批次。
- 卡号查询。
- 发放渠道。
- 激活状态。
- 提货状态。
- 提货记录。
- 冻结、作废、风控。
- 操作日志。

提货卡不是优惠券、满减券、折扣券、储值卡、支付方式或普通营销券。模板层不得把提货卡并入促销折扣或购物车抵扣。

## 营销、客服和直播模板合同

营销模板：

- 普通营销活动、Banner、推荐位可以规划为展示/配置模板。
- 提货卡不归入普通优惠券模板。
- 真实折扣、优惠、满减、积分等会影响订单价格的能力必须单独评估。

客服模板：

- 可以展示会话入口、公告、投诉记录和服务异常。
- 不能直接接真实 IM、短信或外部客服服务，必须走 provider/adapter。

直播模板：

- 可以展示店铺直播状态、直播审核占位和内容运营视图。
- 不接真实推流、聊天室、礼物、打赏、直播交易或结算。

## 风控和系统配置模板合同

风控模板可以展示：

- 商户风险。
- 商品风险。
- 订单风险。
- 提货卡风险。
- 服务通知异常。
- 操作日志。

系统配置模板可以展示：

- 模块开关。
- 市场配置。
- 商户类型开关。
- 支付、短信、物流、IM provider 占位配置。

但这些模板不能生效真实高风险配置。真实 provider、支付通知、退款、对账、结算、权限和履约配置必须有后端验签、幂等、审计和回滚。

## 可变和不可变

可变：

- 菜单分组。
- 首页卡片密度。
- 表格列展示。
- 筛选器布局。
- 标签和状态文案。
- 详情页信息区块。

不可变：

- RBAC 和权限判定。
- 审计记录。
- 支付成功来源。
- 订单状态来源。
- 退款状态来源。
- 结算、佣金、打款来源。
- 履约和配送事实来源。
- provider 真实配置和密钥来源。

2. `admin-template-registry-static`：静态 registry，列出 dashboard/market/merchant/product/pickup/risk 模板 id。

5. `admin-template-system-validation`：typecheck/test/diff 收口。

## 本轮结论

Admin 模板可以继续向国内平台运营后台优化，但必须保持“模板只呈现，事实归后端”。尤其是权限、审计、支付、退款、结算、佣金和履约不能被前端模板或 mock 数据替代。
