# 中国大陆 UX 规格

日期：2026-05-02  
适用范围：MercurJS 中国大陆多商户电商平台本地化改造

## 基线

- 默认语言：zh-CN。
- 默认币种：CNY。
- 默认时区：Asia/Shanghai。
- 手机号：中国大陆手机号；后端合同需要规范化时优先 E.164。
- 地址顺序：中国大陆、省、市、区县、街道/乡镇、详细地址、收货人、手机号、邮编。
- 支付结果：前端只展示 pending/处理中/失败提示；支付成功以后端异步通知为准。

## 当前结构限制

当前仓库包含：

- `packages/api`
- `apps/admin`
- `apps/vendor`

当前未发现：

- `apps/storefront`

因此本规格中的 Storefront 部分是后续接入要求，不代表当前仓库已经存在 Storefront。

## Storefront UX

### 信息架构

后续 `apps/storefront` 应采用中国大陆电商常见信息架构：

- 搜索优先。
- 类目导航清晰。
- 首页突出活动、类目、推荐商品、店铺或商家入口。
- 商品列表支持筛选、排序、价格、销量或销售提示。
- 商品详情展示价格、促销、库存、服务保障、售后入口、商家信息。
- 购物车和结账入口明确。
- 移动端保留粘性购买动作。

### 商品卡

商品卡应至少支持：

- 商品图。
- 商品名。
- CNY 价格。
- 促销或活动提示。
- 销量或销售提示。
- 商家或店铺信息。
- 库存/发货地/服务标签视具体数据可用性展示。

### 商品详情

商品详情应至少支持：

- 商品图集。
- 标题与卖点。
- CNY 价格。
- 促销信息。
- 规格选择。
- 库存与发货信息。
- 店铺入口。
- 售后/退换说明入口。
- 移动端底部粘性加入购物车/立即购买。

### 购物车与结账

购物车和结账必须注意：

- 价格以 CNY 展示。
- 订单、支付、退款逻辑不在前台单方面判定。
- 支付结果页只展示待确认或处理中状态。
- 收货地址表单按中国顺序。
- 手机号按中国大陆规则校验。
- 移动端提交订单按钮稳定粘底，不遮挡内容。

## Admin Panel UX

Admin Panel 是平台运营后台，应采用密集、可扫描、可审计的运营布局，不做营销式页面。

目标一级导航：

- 首页
- 商家管理
- 商品管理
- 订单管理
- 售后管理
- 支付与对账
- 结算管理
- 营销管理
- 客服与消息
- 系统配置

### 首页

首页应聚合运营待办，而不是品牌展示：

- GMV、订单数、商家数、商品数。
- 待审核商家。
- 待发货订单。
- 售后待处理。
- 支付异常。
- 对账差异。
- 待结算或结算失败。
- 风控预警。

第一版可先做只读或空状态，不改变后端业务状态。

### 商家管理

应支持中国平台运营语义：

- 商家 / 店铺术语统一。
- 经营状态。
- 审核状态。
- 资质信息。
- 收款信息。
- 联系人和手机号。
- 店铺地址。
- 成员邀请与权限状态。

不得弱化 RBAC、商家权限或审核规则。

### 商品管理

建议关注：

- 商品审核状态。
- 上下架。
- 违规处理。
- 活动报名。
- 库存扫描。
- 价格和促销。
- 商品类目。

第一批 PR 可只做 IA 和中文化，不改商品审核或上下架逻辑。

### 订单管理

建议关注：

- 中文订单状态。
- 支付状态说明。
- 履约状态。
- 售后入口。
- 支付异常提示。
- 操作时间和失败原因。

不得修改订单状态机、支付确认、退款、履约、订单归属。

### 售后管理

售后应从订单详情中抽象出平台视角：

- 退货。
- 退款。
- 换货。
- 投诉或纠纷。
- 售后原因。
- 处理状态。
- 操作记录。

第一版可为只读聚合入口，链接现有订单售后子路由。

### 支付与对账

建议展示：

- 支付渠道。
- 支付流水。
- 支付通知状态。
- 签名/验签结果。
- 幂等处理状态。
- 对账文件。
- 对账差异。
- 失败原因。

任何支付状态变化都必须来自后端异步通知和 provider 验签。

### 结算管理

建议展示：

- 商家账单。
- 结算周期。
- 平台佣金。
- 退款调整。
- 打款状态。
- 失败原因。
- 操作时间。

结算、佣金、payout 属于高风险串行工作。

## Vendor Panel UX

Vendor Panel 是商家后台，应优化重复商家操作、列表扫描、批量友好布局和移动可读性。

目标一级导航：

- 首页
- 商品管理
- 订单管理
- 物流管理
- 售后管理
- 客服管理
- 店铺管理
- 结算管理
- 评价管理
- 账号权限

### 首页

商家首页建议展示：

- 今日订单。
- 待发货。
- 待处理售后。
- 商品库存预警。
- 店铺状态。
- 待结算金额。
- 消息或客服待办。

第一版可只读，不改变订单、结算或客服状态。

### 商品管理

应支持：

- 商品列表扫描。
- 价格、库存、销量、上下架状态。
- 批量操作入口。
- 活动/促销状态。
- 类目和规格管理入口。

### 订单管理

应支持：

- 待付款、待发货、已发货、已完成、售后中等状态筛选。
- 物流信息。
- 收货地址展示。
- 买家备注。
- 售后入口。

不得改变订单归属、履约状态、退款状态或权限。

### 物流管理

建议聚合：

- 待发货订单。
- 运费模板。
- 发货地址。
- 服务区域。
- 物流单号。
- 轨迹和异常件。

第一版可为只读入口，不接真实物流。

### 售后管理

建议支持：

- 退货。
- 退款。
- 换货。
- 售后原因。
- 处理时限。
- 证据附件。
- 操作记录。

退款和售后状态变更必须作为高风险串行任务处理。

### 客服管理

建议支持：

- 会话列表。
- 未读数。
- 订单关联。
- 商品关联。
- 常用回复。

第一版只设计 `MockChatProvider`，不得删除 TalkJS。

### 店铺管理

建议支持：

- 店铺信息。
- 联系人。
- 中国地址。
- 资质。
- 收款账户。
- 营业状态。

店铺地址应使用中国地址顺序，但不在低风险 PR 中新增数据库字段。

### 结算管理

建议支持：

- 可结算金额。
- 待结算金额。
- 已打款金额。
- 退款调整。
- 佣金。
- 打款状态。

结算、payout、佣金属于高风险串行工作。

## 地址 UX

中国地址表单顺序：

1. 国家/地区：中国大陆
2. 省 / 自治区 / 直辖市
3. 市
4. 区县
5. 街道 / 乡镇
6. 详细地址
7. 收货人
8. 手机号
9. 邮编，可选
10. 默认收货地址 / 默认账单地址

展示格式：

```text
张三 13800138000
上海市 上海市 浦东新区 张江镇 祖冲之路 1000 号 3 幢 201
邮编：201203
```

兼容策略：

- 保持 Medusa 标准字段。
- `province` 承载省。
- `city` 承载市。
- `address_2` 或 `metadata` 过渡承载区县和街道。
- `address_1` 承载详细地址。
- `first_name` 可承载中文完整姓名，`last_name` 可留空。
- 复用 `is_default_shipping` / `is_default_billing`。

## 验证要求

UI PR 必须包含：

- 桌面验证。
- 移动验证。
- 文字不溢出、不遮挡。
- 菜单和路由可达。
- 中文文案一致。
- 权限敏感入口不变。

Storefront PR 还必须验证：

- 首页。
- 搜索/类目。
- 商品列表。
- 商品详情。
- 购物车。
- 结账入口。
- 移动端粘性购买动作。
- 支付结果 pending 状态。

Admin/Vendor PR 还必须验证：

- Admin：`http://localhost:7000`
- Vendor：`http://localhost:7001`
- 商家数据归属不变。
- RBAC 不变。
