# Merchant Role Capability Readiness

更新时间：2026-05-08 17:42 Asia/Shanghai

## 结论

商户类型必须拆成独立角色能力，不能把物料供应商、配送供应商、养殖户、种植户、种苗供应商、外地批发商都混成普通商品商户。

当前阶段只适合定义能力矩阵和只读展示，不适合让角色改变权限、订单归属、结算、佣金或履约。

## 角色矩阵

| 角色 | 消费者默认可见 | 商户侧默认可见 | 需要后台开通 | 主要用途 |
| --- | --- | --- | --- | --- |
| 海鲜档口 | 是 | 是 | 是 | 面向消费者售卖本地海鲜 |
| 冻品商户 | 是 | 是 | 是 | 面向消费者售卖冻品 |
| 干货商户 | 是 | 是 | 是 | 面向消费者售卖干货 |
| 水果蔬菜商户 | 是 | 是 | 是 | 面向消费者售卖水果蔬菜 |
| 物料供应商 | 否 | 是 | 是 | 面向商户卖泡沫箱、包装箱、冰袋、冰块 |
| 配送供应商 | 否 | 是 | 是 | 提供市场配送或商户配送能力 |
| 养殖户 | 否 | 是 | 是 | 上游供给，主要对接商户 |
| 种植户 | 否 | 是 | 是 | 上游供给，主要对接商户 |
| 种苗供应商 | 否 | 是 | 是 | 面向养殖户、种植户和商户 |
| 外地批发商 | 否 | 是 | 是 | 对接本地商户补充货源 |

## 能力定义

### 普通商品商户

包含：

- 海鲜档口。
- 冻品商户。
- 干货商户。
- 水果蔬菜商户。

可见能力：

- 消费者商品流。
- 店铺/档口主页。
- 手机快速上架草稿。
- 商品审核候选。
- 商家装修只读展示。
- 直播状态只读展示。

禁止默认拥有：

- 物料供应商自接单。
- 配送供应商接单。
- 结算规则修改。
- 佣金规则修改。
- 权限管理。

### 物料供应商

面向商户销售：

- 泡沫箱。
- 包装箱。
- 冰袋。
- 冰块。
- 其他市场耗材。

展示边界：

- 不放在消费者首页前排。
- 不混入消费者生鲜商品流。
- 可以在 Vendor / Admin 物料采购或市场服务中展示。

后续开关：

- 是否允许物料供应商自接单。
- 是否需要平台审核后接单。
- 是否允许指定市场可见。

### 配送供应商

提供：

- 市场统一配送能力。
- 商户自配送外包能力。
- 冷链或同城配送能力。

展示边界：

- 可在商户后台和 Admin 配送配置中展示。
- 消费端只看到商户/档口支持的配送方式，不看到内部供应商接单逻辑。

禁止：

- 不直接改变 checkout shipping options。
- 不创建履约单。
- 不接真实物流。
- 不接快递打印。

### 养殖户 / 种植户

定位：

- 上游供给方。
- 主要服务商户或平台采购。

边界：

- 不默认进入消费者商品流。
- 若要对消费者售卖，必须额外开通普通商品商户角色。
- AI 上架或快速上架只能生成草稿。

### 种苗供应商

定位：

- 服务养殖户、种植户和商户。
- 属于供应链上游。

边界：

- 不默认进入消费者首页。
- 不影响普通商品库存。

### 外地批发商

定位：

- 直接对接本地商户。
- 补充异地货源。

边界：

- 可做商户采购可见。
- 不默认对消费者零售。
- 不改变本地市场档口归属。

## Admin 开通规则

Admin 后续应支持：

- 平台级角色开关。
- 市场级角色开关。
- 商户级角色申请。
- 审核状态。
- 审计日志。
- 暂停 / 恢复 / 拒绝。

当前阶段：

- 只能 read-only 或 docs-only。
- 不生效到权限系统。
- 不生效到结算、佣金或订单归属。

## Vendor 展示规则

Vendor 后续应展示：

- 当前商户角色。
- 角色审核状态。
- 所属市场。
- 档口号。
- 可用功能入口。
- 不能使用功能的原因。

当前阶段：

- 只展示 capability view。
- 不隐藏真实权限。
- 不开放真实接单或结算。

## Storefront 展示规则

消费者侧默认展示：

- 普通商品商户。
- 店铺/档口主页。
- 商品。
- 商户直播状态。

消费者侧默认不展示：

- 物料供应商。
- 配送供应商。
- 养殖户 / 种植户。
- 种苗供应商。
- 外地批发商。

例外：

- 这些角色若额外开通普通商品商户角色，可以进入消费者商品流。

## 高风险边界

角色不得直接改变：

- RBAC / permission。
- 订单归属。
- 结算主体。
- 佣金规则。
- 支付方式。
- 退款流程。
- checkout shipping options。
- 真实履约。

## 推荐 PR 顺序

1. `merchant-role-capability-contract`
   - 新增纯 TypeScript role capability view shape。
   - 不新增 API route。

2. `admin-merchant-role-readiness-plan`
   - docs-only。
   - 规划 Admin 商户角色只读面板。

3. `vendor-role-capability-readiness-plan`
   - docs-only。
   - 规划 Vendor 角色提示和功能入口。

4. `storefront-role-visibility-plan`
   - docs-only。
   - 规划消费者侧默认可见性。

## 验收

后续每个 PR 必须说明：

- 是否只读。
- 是否影响权限。
- 是否影响订单归属。
- 是否影响结算/佣金。
- 是否影响消费者商品流。
- 验证命令。
