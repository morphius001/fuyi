# Product Spec Model

## 目标

Fuyi 的商品规格必须由后台结构化维护，前台只负责按规则展示。`¥68-82/斤` 是价格和计价单位，不是规格。消费者需要同时看到商品规格、计价方式、起售数量、库存口径和履约提示。

本模型面向中国大陆本地生鲜/海鲜市场，也要兼容水果蔬菜、市场物料、种苗批发、养殖户/种植户供货和外地批发商对接商户。

## 核心原则

- 规格、价格、库存、履约分开建模。
- 销售单位、计价单位、库存单位、包装单位分离。
- 商品层展示商品本身的信息，档口/商户层展示取送能力。
- 市场统一配送是市场能力，商家可选择是否加入，不能写成商品属性。
- AI 可以生成商品草稿，但必须人工确认后发布。
- 前台所有规格展示都应来自后台字段或后台模板，不在页面写死。

## 单位分离

不要把库存、销售、包装混成一个字段。

示例：

```text
商品：鲜活梭子蟹
规格：公母混装 · 3-5两/只
销售单位：斤
计价单位：斤
起售数量：1斤起
库存单位：筐
包装规格：约20斤/筐
可售库存：剩36筐
价格：¥68-82/斤
```

前台商品卡展示：

```text
鲜活梭子蟹  建议自提
公母混装 · 3-5两/只 · 1斤起
¥68-82/斤
阿海鲜活档 · A区18号 · 剩36筐
```

## 价格类型

| 类型 | 示例 | 使用场景 |
| --- | --- | --- |
| 固定价 | ¥68/斤 | 标准品、物料 |
| 区间价 | ¥68-82/斤 | 海鲜不同大小/公母混卖 |
| 时价 | 今日询价 | 波动大的活鲜、外地批发 |
| 阶梯价 | 10箱起 ¥8/箱 | 物料、批发 |
| 称重后确认 | 估算 ¥314，实称后确认 | 生鲜称重结算 |

## 类目规格模板

### 海鲜/水产

推荐字段：

- 鲜活/冰鲜/冷冻/干货
- 品类：蟹、虾、鱼、贝
- 公母/规格名称
- 单只重量：3-4两/只、4-5两/只
- 起售数量：1斤起、2只起、一筐起
- 称重方式：实称结算、按盒固定
- 商品提示：建议自提、冷链可送、今日可送

前台展示：

```text
公母混装 · 3-5两/只 · 1斤起
```

### 水果蔬菜

推荐字段：

- 品种
- 产地
- 等级：精品、统货、一级果
- 箱规/袋规
- 净重
- 起售数量
- 新鲜度/采摘时间

前台展示：

```text
本地番茄 · 一级果 · 5斤/箱
```

### 市场物料

适用于商户端，不作为普通消费者主链路。

推荐字段：

- 物料类型：泡沫箱、包装箱、冰袋、冰块、周转筐
- 尺寸
- 容量
- 材质
- 件/箱数量
- 起订量
- 阶梯价

前台展示应在商户采购或供应商页面：

```text
泡沫箱 · 60x40x30cm · 10个/组
```

### 种苗批发

推荐字段：

- 品种
- 苗龄
- 规格/长度
- 成活率说明
- 起订量
- 运输方式
- 技术服务说明

前台展示：

```text
南美白对虾苗 · P5-P7 · 10万尾起
```

### 养殖户/种植户供货

推荐字段：

- 主体类型：养殖户/种植户
- 基地位置
- 供货品类
- 批次
- 预计上市时间
- 供货单位
- 检测/认证占位

### 外地批发商

推荐字段：

- 供应地
- 批发品类
- 箱规/件规
- 起订量
- 到货时效
- 冷链/常温
- 对接商户范围

## 前台展示规则

商品卡：

- 商品名 + 商品提示
- 一行关键规格
- 价格/计价单位
- 档口、市场、库存
- 档口取送能力放在档口信息区

商品详情页：

- 完整规格表
- 价格类型说明
- 起售数量
- 库存单位与包装折算
- 称重/时价提示
- 档口取送能力卡

购物车：

- 显示用户已选规格
- 显示估算金额
- 显示称重后确认提示
- 按档口分组确认取送方式

结算页：

- 按档口确认履约
- 实称/时价商品要提示最终金额
- 支付前展示最终确认状态

## 商户快速上架

手机端表单应围绕最少字段：

- 商品名
- 类目
- 规格模板
- 规格/等级
- 单位
- 价格类型和价格
- 库存和库存单位
- 起售数量
- 商品提示
- 图片

必须支持：

- 复制昨日规格
- 常用规格模板
- 批量改价
- 保存草稿
- 发布前确认

落地顺序：

- 第一阶段只保存商品草稿。
- 第二阶段读取规格模板并校验字段完整性。
- 第三阶段 AI 或微信入口只写 suggestion，不直接发布。
- 第四阶段平台审核通过后才进入真实商品创建 workflow。

详细读写拆分见 `docs/vendor-draft-product-readwrite-plan.md`。

## AI 一句话上架

输入示例：

```text
今天梭子蟹公母混装，3到5两一只，68到82一斤，1斤起，剩36筐，建议自提
```

解析结果：

```json
{
  "title": "鲜活梭子蟹",
  "category": "鲜活水产/蟹类",
  "spec_name": "公母混装",
  "size_grade": "3-5两/只",
  "price_type": "range",
  "price_min": 68,
  "price_max": 82,
  "price_unit": "斤",
  "min_order_quantity": 1,
  "sales_unit": "斤",
  "stock_quantity": 36,
  "stock_unit": "筐",
  "product_hint": "建议自提"
}
```

安全规则：

- AI 只生成草稿。
- 发布前必须人工确认。
- 价格、库存、单位、起售数量必须二次确认。
- 高风险字段变更要记录操作日志。
- 不允许 AI 自动修改真实库存或真实订单。

## 后台配置

平台后台需要：

- 类目规格模板管理
- 字段必填/选填配置
- 字段展示位置配置
- 商户类型可用模板配置
- 市场可用类目配置
- 价格类型开关
- 单位字典管理
- 操作日志

商家后台需要：

- 模板化快速上架
- 常用规格保存
- 复制昨日商品
- AI 草稿确认
- 移动端快速发布

## PR 拆分建议

1. 文档与任务文件：只新增规格模型文档。
2. 后台字段设计：API 合同和数据模型设计，不写业务逻辑。
3. 商户快速上架 UI：只做 mock 草稿表单。
4. Storefront 展示接入：商品卡、详情、购物车、结算读取 mock/spec 字段。
5. AI 草稿 API 设计：只设计合同，不接真实 AI。
6. 后端模型实现：串行、带迁移、带测试。

## 验证清单

- 商品卡不再把价格当规格。
- 前台能区分商品提示和档口取送能力。
- 销售单位、计价单位、库存单位、包装单位在文档中分离。
- 海鲜、水果蔬菜、物料、种苗都有模板。
- AI 上架明确必须人工确认。
- 不涉及真实支付、订单、库存扣减、物流或结算逻辑。
