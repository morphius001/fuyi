# 商品规格模板 Admin 配置设计

日期：2026-05-05

本文只做设计，不写业务代码、不创建 migration、不接真实 AI、微信、支付、短信、IM 或物流服务，也不改变商品、库存、订单、支付、退款、结算、佣金或权限逻辑。

## 目标

Fuyi 需要一套由平台后台维护的商品规格模板，支撑本地生鲜/海鲜、果蔬、市场物料、种苗、养殖户/种植户供货和外地批发商供货。

核心原则：

- 规格、价格、库存、履约分开配置。
- `¥68-82/斤` 是价格和计价单位，不是规格。
- 规格模板由 Admin 配置，Vendor 读取后填草稿，Storefront 按模板展示。
- AI 只能基于模板生成草稿字段，不能直接正式发布商品。

## 角色边界

| 端 | 职责 | 不做什么 |
| --- | --- | --- |
| Admin | 管模板、字段、必填规则、展示顺序、适用市场/商户类型、版本、审计 | 不直接代替商户发布商品 |
| Vendor | 读取模板，手机快速上架，复制昨日规格，确认 AI 草稿 | 不绕过平台审核或能力开关 |
| Storefront | 按模板展示消费者能理解的规格、单位、起售量和履约提示 | 不展示后台内部字段和风控原因 |
| API | 提供模板只读、版本、发布/停用、审计合同 | 不改变订单、支付、结算逻辑 |

## 模板结构建议

### ProductSpecTemplate

- `id`
- `key`: 例如 `seafood_live_crab`
- `name`: 鲜活蟹类规格模板
- `category_key`
- `market_scope`: `global`、`market`、`merchant_type`
- `merchant_types`: 海鲜档口、冻品、干货、果蔬、物料供应商、种苗供应商、外地批发商
- `fields`
- `display_rules`
- `validation_rules`
- `status`: `draft`、`active`、`paused`、`archived`
- `version`
- `created_by`
- `updated_by`
- `created_at`
- `updated_at`

### 字段类型

| 字段类型 | 示例 | 说明 |
| --- | --- | --- |
| `text` | 公母混装 | 规格名称、产地、品种 |
| `select` | 鲜活/冰鲜/冷冻/干货 | 标准选项 |
| `number` | 68 | 价格、重量、数量 |
| `unit` | 斤、筐、箱、袋 | 必须来自单位字典 |
| `range` | 68-82 | 区间价、重量范围 |
| `boolean` | 是否时价 | 状态选择 |
| `enum_list` | 建议自提、今日可送 | 商品提示 |

## 标准字段组

| 字段组 | 字段 | 是否常用必填 | 说明 |
| --- | --- | --- | --- |
| 基础 | 商品名、类目、市场、商户、档口 | 是 | 商品归属和消费者识别 |
| 规格 | 规格名称、等级/尺寸、包装规格、起售数量 | 是 | 不能用价格代替规格 |
| 单位 | 销售单位、计价单位、库存单位、包装单位 | 是 | 四类单位分离 |
| 价格 | 价格类型、价格、区间价、阶梯价 | 是 | 只描述价格，不描述规格 |
| 库存 | 可售库存、库存单位、到货状态 | 是 | 不直接写订单库存扣减逻辑 |
| 生鲜 | 鲜活/冰鲜/冷冻、到货时间、称重方式 | 视类目 | 生鲜类目常用 |
| 履约提示 | 商品提示 | 视类目 | 商品层只放建议自提/冷链可送等提示 |

## 类目模板

### 海鲜 / 水产

必填建议：

- 品类：蟹、虾、鱼、贝
- 新鲜度：鲜活、冰鲜、冷冻、干货
- 规格名称：公蟹、母蟹、公母混装
- 等级/尺寸：3-5两/只
- 起售数量：1斤起
- 销售单位：斤
- 计价单位：斤
- 库存单位：筐
- 包装单位：约20斤/筐

消费者展示：

```text
鲜活梭子蟹
公母混装 · 3-5两/只 · 1斤起
¥68-82/斤
阿海鲜活档 · A区18号 · 剩36筐
```

### 水果蔬菜

字段：

- 品种
- 产地
- 等级
- 箱规/袋规
- 净重
- 采摘日
- 起售数量

展示：

```text
本地番茄 · 一级果 · 5斤/箱 · 今日采摘
```

### 市场物料

市场物料面向商户采购或物料供应商工作台，不放在普通消费者首页主链路。

字段：

- 物料类型：泡沫箱、包装箱、冰袋、冰块、周转筐、胶带、标签
- 尺寸
- 容量
- 材质
- 件/组数量
- 起订量
- 阶梯价

展示：

```text
泡沫箱 · 60x40x30cm · 10个/组
```

### 种苗批发

字段：

- 品种
- 苗龄
- 规格/长度
- 起订量
- 成活率说明
- 运输方式
- 技术服务说明

### 养殖户 / 种植户

字段：

- 主体类型
- 基地位置
- 供货品类
- 批次
- 预计上市时间
- 供货单位
- 检测/认证占位

### 外地批发商

字段：

- 供应地
- 批发品类
- 箱规/件规
- 起订量
- 到货时效
- 冷链/常温
- 对接商户范围

## API 合同草案

### Admin

```http
GET /admin/china/spec-templates
GET /admin/china/spec-templates/:id
POST /admin/china/spec-templates
PATCH /admin/china/spec-templates/:id
POST /admin/china/spec-templates/:id/publish
POST /admin/china/spec-templates/:id/pause
GET /admin/china/spec-templates/:id/audit-logs
```

写入要求：

- 需要平台运营权限。
- 必须记录版本。
- 发布前校验字段 key、单位字典、必填规则和展示规则。
- 修改 active 模板时创建新版本，不能直接覆盖历史商品解释口径。
- 发布、暂停、回滚必须写审计日志。

### Vendor

```http
GET /vendor/china/listing-templates?market_id=...&merchant_type=...
GET /vendor/china/listing-templates/:key
POST /vendor/china/product-drafts/from-template
POST /vendor/china/product-drafts/ai/text
```

Vendor 只能读取自己当前市场和商户类型可用的模板。AI 解析结果必须进入草稿，不能直接写真实商品。

### Storefront

```http
GET /store/china/products/:handle/spec-view
```

Storefront 应收到裁剪后的展示视图：

```json
{
  "title": "鲜活梭子蟹",
  "spec_line": "公母混装 · 3-5两/只 · 1斤起",
  "price_line": "¥68-82/斤",
  "stock_line": "剩36筐",
  "product_hint": "建议自提",
  "stall_fulfillment": ["市场统一配送", "档口自送", "到店自提"]
}
```

## 版本与回滚

- 模板发布后生成不可变版本号。
- 商品草稿保存使用的模板版本。
- 已发布商品展示应能追溯当时模板版本。
- 回滚只影响新草稿和后续编辑，不应悄悄改变历史订单或已确认结算口径。

## 风险边界

- 模板不是商品审核。
- 模板不是库存系统。
- 模板不是支付、退款、结算或佣金规则。
- 市场统一配送是市场/商户能力，不是商品属性。
- AI 草稿不能自动发布。
- 高风险类目、证照、食品安全和平台处罚仍需独立审核流程。

## PR 拆分建议

1. 文档和字段字典。
2. Admin 规格模板只读 UI。
3. Vendor 读取模板并用于手机快速上架草稿。
4. AI 草稿结构化字段对齐模板。
5. Storefront 商品卡/详情读取展示视图。
6. Admin 模板写接口、版本和审计。
7. 与真实商品创建 workflow 对接，单独评审。

## 验证步骤

- 文档审查：确认规格、价格、库存、履约四类字段没有混用。
- UI 审查：Vendor 快速上架显示规格模板和单位拆分。
- Storefront 审查：商品卡不把价格当规格。
- 后端评审：所有写操作必须有权限、版本、审计和回滚策略。
