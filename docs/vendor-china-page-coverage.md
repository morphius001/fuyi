# Vendor China Page Coverage

本文档记录中国商家后台当前页面覆盖状态，避免后续把 mock 商家工作台误认为真实业务能力。

## 总体边界

- 当前 Vendor 是中国大陆商家后台 UI 壳和静态 mock 数据。
- 不接真实商品、订单、库存、售后、支付、退款、结算、佣金、权限、短信、IM、物流、电子面单、直播或 AI 服务。
- 不写真实 app id、token、access key、secret、私钥、证书、快递月结号或 IM 凭证。
- AI 上架只能生成草稿，必须商户确认后才可提交审核或发布。
- 市场统一配送是可选能力，商户可选择统一配送、自行配送或混合模式；真实开关后续必须由后端能力控制。
- 物料供应商、配送供应商、上游养殖户/种植户、种苗批发和外地批发商是 B 端能力，不进入消费者首页前排。

## 路由和渲染方式

Vendor 当前是单页应用：

- 入口：`apps/vendor/src/App.tsx`
- 数据：`apps/vendor/src/china/data/vendorMockData.ts`
- 样式：`apps/vendor/src/styles.css`

导航由 `menuItems` 控制，点击后切换 `activePageId`。除首页外，大部分页面使用 `ManagementPage` 通用只读管理页。

专门页面骨架：

| 页面 | 渲染方式 | 说明 |
| --- | --- | --- |
| `home` | `HomePage` | 商家首页，展示市场、档口、模块开通、经营指标、待办、风险、快捷入口、上游供给摘要。 |
| `shopDecoration` | `ManagementPage` + `ShopDecorationSkeleton` | 店铺主页装修草稿，覆盖店招、公告、今日鲜货、资质、配送说明和直播状态。 |
| `aiListingDraft` | `ManagementPage` + `AiListingDraftSkeleton` | AI 一句话上架草稿，仅生成结构化草稿，不自动发布。 |

## 当前产品要点

手机快速上架：

- 面向商户日常鲜货上架，移动端必须比电脑端简单。
- 适合今日鲜货、常卖商品模板、批量今日价和图片快速补充。
- 当前不提交真实商品、不改库存、不发布。

AI 草稿上架：

- 支持“微信或其它入口一句话让它上架”的未来能力。
- 当前必须停留在草稿和结构化预览，商户确认前不得发布。
- 真实接入时需要图片、规格、价格、库存、类目、敏感词和风控校验。

店铺装修：

- 商家应有自己的主页，尤其是市场/档口型商户。
- 店铺页承载店招、公告、今日鲜货、商品分组、资质、配送说明和直播状态。
- 自提/配送方式应主要展示在商家店铺页或订单履约上下文，不作为消费者首页主卖点。

市场和配送：

- 商户属于一个或多个市场，可有档口号。
- 市场有营业时间、公告、配送规则和能力开关。
- 统一配送是市场能力，但是否使用应由商户选择。

B 端供应：

- 市场物料、配送供应商、养殖户、种植户、种苗批发和外地批发商属于商户生态。
- 这些能力需要 Admin 后台控制是否开放，并通过商户类型/市场能力配置决定菜单可见性。

## 后续接真实能力前必须补齐

- 后端商户类型、市场归属、档口号和多市场关系模型。
- 后端模块开关、市场能力开关和商户能力开关。
- 移动端快速上架的草稿保存、校验、审核和发布流程。
- AI 草稿的安全边界、敏感词、规格模板和人工确认流程。
- 店铺装修草稿、预览、发布、审核和回滚机制。
- 配送、快递打印、IM、短信、直播、结算等 provider/adapter 边界。
