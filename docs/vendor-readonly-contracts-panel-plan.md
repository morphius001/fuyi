# Vendor Readonly Contracts Panel Plan

更新时间：2026-05-08 21:46 Asia/Shanghai

## 结论

Vendor 可以做一个“我的能力边界”只读面板，让商户知道当前平台为自己开放或规划了哪些能力，但不能让商户在这里直接发布商品、发货、打印面单、开直播或提交真实提货履约。

本任务只做规划，不修改 `apps/vendor/**`。

## 信息架构

建议页面位置：

```text
首页
  -> 我的能力边界
```

或：

```text
店铺管理
  -> 能力与开通状态
```

页面结构：

1. 商户角色
   - 当前角色。
   - 所属市场。
   - 档口号。
   - 消费者默认可见性。
   - 需要平台开通的能力。

2. 快速上架
   - 手机草稿字段。
   - 规格模板来源。
   - AI suggestion 边界。
   - 审核候选说明。

3. 店铺装修
   - 当前公开快照。
   - 可编辑模块占位。
   - 审核/发布尚未接入说明。

4. 履约与面单
   - 到档自提。
   - 商家自配送。
   - 市场统一配送。
   - 配送供应商。
   - 快递/冷链面单 mock 边界。

5. 提货卡履约认知
   - 提货单不是普通已支付订单。
   - 商家后续只处理归属自己的提货履约单。
   - 不查看卡密。

6. 直播状态
   - 预告/回放占位。
   - 不接真实推流和 IM。
   - 不触发直播交易。

## 商户可见但不可操作

Vendor 面板可以展示：

- `readOnly`。
- `runtimeEnabled`。
- 当前可见原因。
- 未开放原因。
- 后续需要平台审核或配置的事项。

Vendor 面板不能提供：

- 立即发布真实商品。
- 初始化库存。
- 确认发货。
- 生成真实运单号。
- 打印真实面单。
- 创建真实直播间。
- 查看或生成卡密。
- 修改结算、佣金或权限。

## 数据来源

第一版 UI 可使用前端常量或后端只读 contract 聚合。

后续如果接后端：

- 只能 GET。
- 必须按当前登录商户过滤。
- 返回只读 view。
- 不允许 POST/PATCH/DELETE。
- 不允许把 contract 当权限判断。

## UI PR 边界

后续 UI PR 可修改：

- `apps/vendor/**`

但禁止：

- 修改 `packages/api/**`，除非任务明确是后端只读 GET route。
- 新增真实保存、发布、发货、打印、开播、兑换或结算逻辑。
- 引入新依赖。

## 验证要求

UI PR 至少验证：

- Vendor build。
- Vendor lint。
- 页面 200 或截图。
- 移动端可读。
- 操作型按钮不存在或禁用。
- 文案明确“只读/未生效/待平台开通”。

## 下一步

建议继续做 `storefront-readonly-contracts-visibility-plan`，规划消费者侧哪些状态可以展示，哪些必须隐藏。
