# Vendor Role Workspace Template V2 Plan

更新时间：2026-05-09 Asia/Shanghai

## 目标

规划商户后台角色工作台 v2 模板预览。商户端不应该只有一个通用首页，而应该根据商户角色显示不同重点。

当前不改页面，只定义后续实现验收。

## Template ID

```text
vendor-role-workspace-v2
```

## 读取 View Model

后续实现应只读取稳定展示模型：

```text
merchant_role
market_memberships
booth_profiles
enabled_capabilities
readonly_contracts
today_kpis
action_todos
quick_actions
product_or_supply_status
fulfillment_status
risk_notices
```

不能直接读取或改变：

- payment success
- order ownership
- refund status
- settlement / commission / payout
- permission
- fulfillment / waybill
- provider config
- real credentials

## 角色布局

### 普通生鲜/海鲜商户

首页重点：

- 今日订单。
- 待发货/待自提。
- 商品库存。
- 手机快速上架。
- 店铺装修。
- 售后和评价。

快捷入口：

- 上架商品。
- 查看订单。
- 处理售后。
- 装修店铺。
- 客服消息。

### 水果蔬菜商户

在普通商户基础上加强：

- 规格/单位。
- 产地。
- 批次。
- 保鲜状态。
- 到货时间。

### 物料供应商

首页重点：

- 商户采购订单。
- 物料库存。
- 报价。
- 配送/自提说明。
- 发票或结算占位。

物料供应商面向商户，不面向消费者首页。

物料类型：

- 泡沫箱。
- 包装箱。
- 冰袋。
- 冰块。
- 打包耗材。

### 配送供应商

首页重点：

- 服务市场。
- 服务区域。
- 运力状态。
- 接单状态。
- 异常记录。
- 路线/面单占位。

配送供应商“可接单”是高风险能力，必须另走：

- 权限。
- 履约订单归属。
- 配送状态回写。
- 结算。
- 异常责任。
- 操作日志。

模板不能直接确认发货、创建真实履约、生成真实运单或触发结算。

### 养殖户/种植户

首页重点：

- 供给批次。
- 可供品类。
- 报价。
- 对接商户。
- 产地/资质。
- 履约承诺。

上游供给不直接进入消费者首页。消费者可以在商品/店铺中看到来源说明，但不能看到内部对接和结算关系。

### 种苗供应商

首页重点：

- 种苗品类。
- 供应周期。
- 对接养殖户/种植户/商户。
- 报价。
- 资质。

### 外地批发商

首页重点：

- 跨区域供给。
- 可供品类。
- 对接商户。
- 履约承诺。
- 风险和时效提示。

## 手机快速上架

手机快速上架应作为普通商户和部分供应方的草稿工具：

- 图片。
- 一句话描述。
- 规格模板。
- 价格和单位。
- 库存/供应状态。
- 保存草稿。
- 提交审核。

不能直接：

- 发布商品。
- 写真实库存。
- 绕过审核。
- 创建订单。
- 触发支付。

## AI 草稿

AI 只能是助手：

- 生成标题建议。
- 生成规格建议。
- 生成类目建议。
- 提示缺失字段。
- 生成审核候选。

AI 输出必须人工确认，不能自动发布、自动承诺库存或自动生成真实价格策略。

## 店铺装修 Preview

Vendor 工作台可以展示店铺装修 preview：

- 头图。
- 公告。
- 推荐分组。
- 资质。
- 配送/自提说明。
- 直播状态。

装修 preview 不能改变：

- 商品事实。
- 库存。
- 价格。
- 订单。
- 支付。
- 退款。
- 结算。
- 佣金。
- 权限。
- 履约。

## 验收清单

后续实现 PR 必须验证：

- 普通商户工作台显示商品、订单、售后、装修和快速上架。
- 物料供应商工作台不出现消费者商品流入口。
- 配送供应商工作台不直接确认发货或创建真实面单。
- 上游供给工作台不进入消费者首页主路径。
- 手机快速上架和 AI 草稿均停在草稿/审核候选。
- Vendor lint/build 通过。
- 不修改 payment/order/refund/settlement/commission/payout/permission/fulfillment runtime。

## 回滚方式

实现时必须保留：

- 可切回 `vendor-role-workspace-v1` 的模板 id。
- 旧商户首页或旧工作台入口。
- 不改变 API route 或数据库。
- 不改变真实订单、结算、履约和权限。

## 本轮结论

Vendor 工作台 v2 的核心是按角色拆清楚。普通商户、物料供应商、配送供应商和上游供应方各自要看到自己的工作，不应该挤进同一个杂糅首页。
