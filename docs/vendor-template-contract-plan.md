# Vendor Template Contract Plan

更新时间：2026-05-08 Asia/Shanghai

## 目标

为商户后台建立模板合同。Vendor 不是单一卖家后台，而是未来要支持普通生鲜/海鲜商户、水果蔬菜商户、物料供应商、配送供应商、养殖户/种植户、种苗供应商和外地批发商的角色化工作台。

本任务只做规划，不修改 `apps/vendor/**`。

## Vendor 定位

Vendor 是商户和供应方的工作台。它应该让不同角色快速完成自己的日常动作：

- 普通商户：看订单、上商品、处理售后、装修店铺、维护配送/自提说明。
- 水果蔬菜商户：管理规格、产地、批次、保鲜和供应状态。
- 物料供应商：面向商户卖泡沫箱、包装箱、冰袋、冰块等市场物料。
- 配送供应商：维护配送能力、服务区域、异常和接单状态。
- 养殖户/种植户：对接商户，提供上游供给、批次和报价。
- 种苗供应商：对接养殖户、种植户和商户，提供种苗批发能力。
- 外地批发商：对接本地商户，提供跨区域供给和履约承诺。

## 首页模板合同

Vendor 首页模板建议由这些 slot 组成：

```text
role_context
today_kpis
action_todos
quick_actions
store_status
product_or_supply_status
fulfillment_status
service_messages
risk_notices
capability_boundary
```

首页应根据商户角色切换重点：

- 普通商户：订单、商品、售后、库存、店铺装修。
- 物料供应商：商户采购订单、物料库存、报价、配送。
- 配送供应商：接单状态、配送区域、异常、面单/路线占位。
- 上游供应方：供给批次、报价、对接商户、履约承诺。

首页模板不能直接执行：

- 确认付款成功。
- 真实退款。
- 真实结算或打款。
- 修改佣金。
- 修改权限。
- 创建真实履约或真实面单。

## 角色模板合同

角色模板建议读取：

```text
merchant_role
market_memberships
booth_profiles
enabled_capabilities
readonly_contracts
risk_boundaries
```

每个角色可以看到不同菜单和卡片，但真实可见性不能只由前端模板决定。角色、权限、市场归属、档口号和结算主体必须由后端合同和审计支持。

## 手机快速上架模板合同

手机快速上架应尽量像 App 工作流：

- 拍照或选择图片。
- 一句话或短表单填写商品。
- 选择规格模板。
- 填价格、单位和库存。
- 保存草稿。
- 提交审核。

模板可展示：

```text
draft_product
spec_template
image_slots
price_unit_fields
ai_suggestion
review_candidate
validation_messages
```

模板不能直接创建真实商品、绕过审核或写库存。真实发布必须进入后端商品创建和审核流程。

## AI 上架草稿模板合同

AI 接口可以作为草稿助手：

- 从一句话生成商品草稿。
- 从图片/语音/微信输入生成候选字段。
- 生成规格、标题、描述和类目建议。
- 给出缺失字段提示。

AI 模板不能：

- 自动发布商品。
- 自动承诺库存。
- 自动生成真实价格策略。
- 自动创建订单或支付。
- 自动绕过平台审核。

AI 输出必须进入草稿和人工确认流程。

## 店铺装修模板合同

商家店铺应该有自己的主页装修。Vendor 模板应支持：

- 店铺头图。
- 店铺公告。
- 主营类目。
- 商品分组。
- 推荐商品。
- 资质展示。
- 配送/自提说明。
- 正在直播状态。

店铺装修可以影响消费者看到的店铺页展示，但不能改变商品事实、价格、库存、订单、支付、退款、结算、佣金、权限或履约规则。

## 物料供应商模板合同

物料供应商面向商户，不面向消费者首页。

模板应支持：

- 泡沫箱。
- 包装箱。
- 冰袋。
- 冰块。
- 打包耗材。
- 商户采购订单。
- 报价和库存。
- 配送或自提说明。

物料采购如果未来进入真实交易，必须单独定义商户采购订单、发票、结算和履约边界，不能复用消费者商品流糊过去。

## 配送供应商模板合同

配送供应商模板应支持：

- 服务市场。
- 服务区域。
- 营业时间。
- 运力状态。
- 异常记录。
- 接单状态。
- 面单/路线占位。

配送供应商“可接单”是高风险能力，后续必须单独处理：

- 权限。
- 履约订单归属。
- 配送状态回写。
- 结算。
- 异常和责任。
- 操作日志。

模板不能直接确认发货、生成真实运单、回写订单物流状态或触发结算。

## 上游供给模板合同

养殖户/种植户、种苗供应商和外地批发商属于上游供给关系。

模板应支持：

- 供给角色。
- 可供品类。
- 批次。
- 产地。
- 报价。
- 对接商户。
- 履约承诺。
- 资质和风险提示。

上游供给不直接进入消费者首页主路径。消费者可以在店铺或商品详情里看到“产地/来源/供应说明”，但不应看到内部对接和结算关系。

## 可变和不可变

可变：

- 首页卡片。
- 菜单分组。
- 角色工作台。
- 手机快速上架表单布局。
- AI 草稿展示方式。
- 店铺装修 preview。
- 物料和配送供应商专属页面布局。

不可变：

- 真实商品发布流程。
- 订单归属。
- 支付成功来源。
- 退款和售后状态来源。
- 结算、佣金、打款来源。
- 权限和账号角色来源。
- 履约和面单事实来源。
- provider 真实配置和密钥来源。

## 后续 PR 建议

1. `vendor-template-view-shape`：定义 Vendor template view shape，不接页面。
2. `vendor-role-template-registry-static`：静态 registry，列出普通商户、物料供应商、配送供应商和上游供给模板 id。
3. `vendor-mobile-listing-template-plan`：规划手机快速上架 v2，不写页面。
4. `vendor-shop-decoration-template-plan`：规划店铺装修 preview 模板，不写真上传。
5. `vendor-template-system-validation`：typecheck/test/diff 收口。

## 本轮结论

Vendor 后续要按角色做模板，而不是所有商户共用一个杂糅首页。模板可以让商户端更好用，但真实发布、发货、退款、结算、佣金、权限、履约和配送供应商接单必须继续走后端合同和高风险串行任务。
