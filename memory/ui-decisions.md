# UI Decisions

## 2026-05-15 Admin 平台首页卡片化

- 平台首页中承载运营关注项的横向分隔行，优先使用卡片网格而不是长条列表。
- `运营待办` 使用桌面三卡横排、移动单列；`风险提醒` 与 `近期重点模块` 使用桌面卡片网格、移动单列。
- 该调整仅改变 Admin 展示壳视觉，不接入真实订单、支付、售后、结算、佣金、权限、履约或物流写路径。

## 2026-05-15 Admin 单位级权限开关

- 平台模块开关不能只做全局开关，还需要按经营单位控制能力可见性。
- 后台应给运营可切换的能力选项，例如海鲜档口可以只打开海鲜交易、提货卡、快递打印，隐藏直播、种苗批发、市场物料等无关入口。
- 当前最小闭环应包含 Admin API 保存配置、Vendor effective view 读取和 Vendor 菜单 / 首页入口过滤；不能停留在纯 Admin UI。
- 可上线前应优先使用 PG-first 配置和审计事件，API 重启后仍能读取运营开关。
- Admin 卡片里需要展示经营单位绑定的 seller handle / seller id，让运营能控制“哪个商户后台读取哪套单位配置”，而不是只切全局能力项。
- 真实上线仍需要真实商家身份绑定和后端权限 enforcement；菜单可见性不等于 RBAC 授权。

## 2026-05-16 单位权限独立入口

- 单位级权限开关必须有独立 Admin 入口，不能长期藏在“平台全局模块开关”页里；否则运营会合理误解为全局配置。
- Admin 首页快捷入口应能直接进入 `单位权限开关`，避免用户从平台首页看不到可操作控制面。
- Vendor 首页需要直接展示当前经营单位的“已开通 / 已隐藏”模块快照，让运营刷新商户端时能马上判断后台配置是否生效。
- 店铺装修、店铺资料、数据中心这类商户后台入口也必须挂到单位级模块上；不能因为它们不是交易模块就永远可见。
